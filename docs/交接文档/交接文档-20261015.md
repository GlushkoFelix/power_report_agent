## 5 硬约束与已知坑（**动手前先读这一节**）

1. **评测一律 ≤30 题/批 + `eval_merge.py` 合并** —— `P-030` 已两次教训（单批 120 中断两次，共浪费 ≈25 万 tokens）。
   中断后的抢救打法：`eval_rebuild.py --from-run <批次> --name "<新名>" --mark-source-failed`（0 额度）→ 只补跑缺失题。
2. **引用成绩必须带四要素**：配置 / 端点 / 提示词版本 / **时段**（否则数字之间不可比）。
3. **`enable_thinking` 在本端点的最终口径是"发送 `false`"** —— 两轮实测结论**相反**：
   解读形态探针倾向不发，但**120 题全量**证明不发会让生成质量掉 17 个百分点（`P-035`）。
   换端点/换模型**必须用真探针 + 小批真实评测复测**（`02.data\tmp\_latency_probe3.py` 可复用）。
4. **工具的批量删除保护**（>500 文件/轮）→ 用"**移出**"代替"删除"（本会话实践中有效的姿势）。
5. **PowerShell 内联引号会丢** → 复杂/含中文引号的命令**写成 `.py` / `.cmd` 脚本文件再执行**（本会话多次踩）。
6. **8001 是外部托管进程，且其客户端可能残留为脚本模型**（`P-028`）→ 评测/演示用**自控 8003**，并跑健康门禁。
7. **"重启没生效"也要防**（`P-029`）：起服务后核对**端口持有者是否可见**（`Get-CimInstance Win32_Process`）+ 关键字段。
8. **解读永不空白**是需求方要求：解读超时/解析失败 → 服务端用结果表生成「**自动摘要**」（正文自报来源）→ 界面永远有结论（`提速实验 §5`）。
9. **N2 ≤8s 未达标**（遗留项，如实登记）：受"slot+gen 两次串行调用"限制；最好观测 **11.7s**（快时段）。
10. **自控服务会被外部杀掉**（2026-10-15 实测两次：8003/8080/8005 用普通后台方式拉起后消失，`curl` 全 000，
    日志里**没有崩溃痕迹**）→ 常驻姿势：`schtasks /create /tn <名> /tr "cmd /c <脚本>.cmd" /sc ONCE /st 23:59
    /ru %USERNAME% /it /f` + `schtasks /run /tn <名>`；跑长任务前加**自愈检查**
    （本日新增 `02.data\tmp\_t2_ensure.cmd <端口> <任务名>`，可直接复用；它用 `ping` 当 sleep——`timeout` 在输入被重定向时不可用）。
11. **`.cmd` 文件必须纯 ASCII**：cmd 按 **GBK** 解析，UTF-8 中文注释会破坏后续行——本日两次踩到
    （`_gate_tsc.cmd` 的 `cd /d` 被跳过导致 npm 在 `System32` 里找 package.json；`_run8005.cmd` 整条不执行）。
    要写中文说明，写进 `.py` / `.md`，别写进 `.cmd`。
12. **工具命令里不要混用 `powershell -Command` 与 `&`**：会被整段包成临时 `.ps1` 解析，报"不允许使用与号"。
    混用时**先落成 `.cmd` / `.py` 文件**再执行。
13. **Windows 下自写启动脚本必须有 `if __name__ == "__main__":` 守卫**：multiprocessing 用 spawn，
    沙箱进程池会**重新 import `__main__`**——没有守卫时子进程会把 uvicorn 再起一遍（抢端口 + "沙箱进程池预热失败"，本日踩到）。
