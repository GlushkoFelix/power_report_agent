## 3 探针实测结论（重要）

两个探针均为 `max_tokens=8`、问"只回复 OK"：

| 探针 | 结果 | 解读 |
| --- | --- | --- |
| A：带 `enable_thinking: false` | HTTP 200 / 1490 ms / 41 tokens | **参数被端点接受**（不会像 `glm-5.3` 那样 400）✓ |
| B：不带该参数 | HTTP 200 / 1206 ms / 41 tokens | 与 A **完全一致** |

两者的 `usage.completion_tokens_details` 都是 **`reasoning_tokens = 8`、`content` 为空**：
即 8 个输出 token **全被"思考"吃掉**、没留下正文 —— **该参数被接受但疑似未生效**
（不发送时的表现也相同）。

### 由此推出的三条实操约束

1. **思考是计费的**：每问的 token 消耗会明显高于 `qwen3.8-flash`（后者实测约 8–10K/问），
   演示前务必先估额度；
2. **`LLM_MAX_TOKENS=2048` 偏紧**：思考先占输出额度，长题（多指标 / 长解读）有**JSON 被截断**
   的风险（这与 `glm-5.3` 那次 4/14 题 `E_LLM` 是同一机制）→ 建议上调到 4096；
3. **8s 解读上限可能被思考吃满**：表现为"界面没有解读文字"（表格与图表不受影响）。
   演示时如需解读，可比照 2026-09-22 尾段评测的做法**临时放宽** `NARRATIVE_TIMEOUT_SECONDS`。

> 结论：**"能不能关思考"这一条没拿到想要的答案**，但拿到了更重要的东西——它被接受、不报错，
> 且已知副作用与应对办法。后续要不要再花额度探明"到底能不能关"，建议放在真正需要压延迟时再做。

## 4 端口问题（连带发现）

Windows 当前的 **TCP 保留端口段包含 `5164–5263`**，把前端惯用的 **5173**（以及 PPT 预览的 **5180**）
圈进去了 → Vite 启动报 `EACCES: permission denied 0.0.0.0:5173`，与代码无关。

| 处理 | 说明 |
| --- | --- |
| **已采用** | 前端改起在 **8080**（不在任何保留段内）✓；`8080` 与 5173 一样走 Vite 代理 `/api` → 8000，功能完全一致 |
| 备选 A | 用管理员权限释放保留段（`netsh int ipv4 set dynamicport tcp …` 或重启 `winnat`），再回到 5173 |
| 备选 B | 把项目文档与说明里的 5173 全部改成新端口（`部署运维手册`、附录 B、移动端访问说明等） |

⚠️ 该保留段是**随系统状态变化**的（此前 5173/5180 可用，现在不可用）→ 任何"固定端口"的说明
都可能失效；演示前**先确认端口监听状态**比记端口号更可靠。

## 8 一键脚本已重建（③）

| 文件 | 作用 |
| --- | --- |
| `start.bat` | 薄启动器（双击即用），参数：`--no-open` / `--no-reload` / `--no-pause` |
| `start.ps1` | 真正逻辑：环境检查 → **端口自检**（读 `netsh` 保留段）→ 起后端(8000)/前端(自动选) → 轮询 health/HTTP → 打印 URL → 写 `02.data\tmp\_ports.json` |
| `stop.bat` / `stop.ps1` | 精确停止：按端口 + **兜底清扫**（父监督进程）；带祖先链保护与进程名白名单；**不碰** PPT 预览端口 |

**实测**：`start.bat --no-open --no-pause` → 环境检查 ✓、后端已在运行则跳过 ✓、
前端自动选 **8080** 并 200 就绪 ✓；`stop.bat` → 精确 `[kill]` 前端进程 ✓（详见问题 `P-015` / `P-016`）。

> ⚠️ 一个环境性注意（不影响你自己用）：**由 IDE/命令面板等外部工具"托管启动"的服务进程**，
> 其监督进程在 `Get-CimInstance` 里查不到（无名称/无命令行），脚本无法也不应去终止；
> 你自己双击 `start.bat` 起的服务，`stop.bat` 可以正常精确停止。
