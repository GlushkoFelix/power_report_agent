## 一、要起的东西（顺序：库 → 后端 → 前端）

| # | 步骤 | 命令（PowerShell） | 成功标志 |
| --- | --- | --- | --- |
| 0 | **端口自检**（30 秒，**2026-10-19 新增**） | `Get-NetTCPConnection -LocalPort 8080,8003 -State Listen -ErrorAction SilentlyContinue \| Select-Object LocalPort,OwningProcess` | 两端口**都没有输出** = 空闲 |

| 3 | 前端（指向真模型后端） | `Start-Process 02.data\tmp\_run8080.cmd -WindowStyle Hidden` | 见下方**门禁 3** |

> ⚠️ **第 0 步为什么要加（2026-10-19 实测踩到）**：本机 8080 被**另一个项目**占了 ——
> `agent-platform-java`（`java -jar …agent-platform-backend…jar`，10:59 启动，监听 `0.0.0.0:8080`）。
> `_run8080.cmd` 带 `--strictPort`，端口被占时**直接启动失败**（日志在 `02.data\tmp\_fe8080.log`，
> 报 `EACCES` 或 `Port 8080 is already in use`），而浏览器打开 8080 会是**别人的服务**
> （实测返回 `{"status":"ok","service":"agent-platform"}`）—— 答辩现场最容易在这里翻车：
> 页面能开、但不是我们的前端。
> **处置**：① 先停那个 Java 服务；或 ② 临时换端口 ——
> `cd 01.code\frontend; $env:VITE_BACKEND="http://127.0.0.1:8003"; npm run dev -- --port 8090 --strictPort --host 127.0.0.1`
> （`VITE_BACKEND` 必须显式给，否则代理默认打到 8000；`--host 127.0.0.1` 是为了在**受限环境**下也能起，
> 正常演示不必加，配置里默认 `0.0.0.0` 是为了让手机能访问，见实训附录 B 步骤 7）
>
> `_run8003.cmd` = `uvicorn app.main:app --host 127.0.0.1 --port 8003`（**不带 `--reload`**，跑批/演示稳定）；
> `_run8080.cmd` 里已 `set VITE_BACKEND=http://127.0.0.1:8003`。

## 三、已知坑（今天真实踩过，逐条规避）

| 坑 | 表现 | 规避 |
| --- | --- | --- |
| **8001 是外部托管进程，且其客户端曾残留为脚本模型** | 页面能答，但像模板、数字与问题无关 | **不要用 8001 演示**；要用就先重启它并跑门禁 2 |
| 前端代理目标改错 | 页面能开、接口全 404 或答非所问 | 起前端时务必 `VITE_BACKEND=http://127.0.0.1:8003` |
| `.env` 含真实 Key | — | 见《部署手册》§9.4；**`.env.bak_*` 已删**，开发树只剩 `.env` + `.env.example` |
| 工具的**批量删除保护**（>500 文件） | 清理动作报 `SAFE_DELETE_BULK_CONFIRM_REQUIRED` | 用"**移出**"代替"删除"（或分批） |
| 端点**慢时段** | 快时段 ~11.7s；慢时段单题 **20–40s**（2026-10-14 晚实测最长 52.8s） | 按"单题 **12–20 秒**（快）/ 最多 **40 秒**（慢）"预期；**别在同一题反复追问**（每次真实计费）。软超时已放宽到 生成 40s / slot 20s（`P-038`）→ 慢时段**宁可多等，也不再 25 秒报错丢题** |
| 解读被超时跳过 | 界面**仍有**解读（自动摘要） | 正常现象：模型解读 or「自动摘要」，正文会自报来源 |

## 四、三句如实说明（被问到时的口径）

1. **耗时**：快时段单题 ≈11.7 s（gen 5.8 s + 解读 5.1 s）；慢时段 20–29 s，属**供应商侧时段波动**。
2. **解读**：模型解读（`qwen3.8-flash`，约 3 s；2026-10-16 由 `glm-5.3-flash` 换掉——它现在返回空正文）**或**「自动摘要」（服务端用结果表算出的结论）——
   **界面永远有结论**，这是 2026-10-14 的需求方要求（解读是本项目的交付物）。
3. **120 题成绩**：**prompt-v3.10 × 最终配置 = 108/120 = 90.0%**（2026-10-14 晚，四段合并；
   首轮 19 题属端点慢时段超时 → 重跑 18/19 通过）；上一版 **prompt-v3.9 = 116/120 = 96.7%**（合并口径）；
   旧端点历史 **118/120 = 98.3%**（2026-09-18）。**三者时段不同、不可直接比较**（慢时段单题可达 37–53 s）。
