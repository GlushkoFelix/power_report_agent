## 2 ② 前端断言：怎么做到零额度且不打扰现有环境

界面回归的**正确环境**是离线脚本模型（脚本头部就写明"依赖后端离线脚本模型（无需 Key）"），
所以临时搭了一套**旁路环境**，跑完即停：

```
8002  后端：LLM_API_KEY=sk-xxxxxx（占位值 → 配置层判为"未配置" → 回落离线脚本模型）
            ORCHESTRATOR=langgraph
8082  前端：VITE_BACKEND=http://127.0.0.1:8002
→ node 01.code/tools/ui_flow_check.mjs      （带 UI_BASE=http://127.0.0.1:8082）
→ 跑完停掉 8002/8082；你的 8000 / 8080 全程未动
```

**顺带修的一处硬编码**（`P-014` 的后遗症）：`ui_flow_check.mjs` 里 `BASE` 原写死
`http://127.0.0.1:5173`，而 Windows 保留端口段把这台机器的 5173 圈进去了（本项目前端已改 8080）
→ 改成 **`process.env.UI_BASE || 'http://127.0.0.1:5173'`**（默认口径不变，可用环境变量覆盖）。
**端口号不是稳定契约**，脚本写死端口 = "代码没坏但跑不起来"。

> 口径备注：脚本实际输出 **32 条 PASS**（架构文档旧记"31 条断言"）→ 差异留待阶段 7 与文档一同核对。

## 4 ④ 延迟 / 成本对比（真实模型 `deepseek-v4.1-flash`）

同一问题（报表 `r_monthly`，问"按月看 2009 年总用电量的趋势"）：

| 指标 | legacy 显式编排 | **LangGraph 状态图** | 说明 |
| --- | --- | --- | --- |
| 首字延迟 | 20 ms | **17 ms** | 真流式未退化（事件产生即推送，ADR-018） |
| 端到端 | 13.0 s | 15.4 s | 差异主要来自**模型自身波动**（同为思考型模型，两次 completion 不同） |
| tokens | 9,870 | **8,609** | 同上（模型输出长度波动，非编排引入） |
| 结果 | 12 行 × 2 列 + 图表 + 解读 122 字 | 12 行 × 2 列 + 图表 + 解读 145 字 | 均 `success`，SQL 正确 |

> 结论：**编排方式不是耗时/成本的主因**——模型侧占绝对主导（单题 8.6–9.9K tokens、13–15 秒），
> 图编排自身引入的开销只在**毫秒级**（见 §3 的 p95 对比）。
