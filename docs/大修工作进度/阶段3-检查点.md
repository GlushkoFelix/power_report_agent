## 1 做了什么

| # | 产物 | 说明 |
| --- | --- | --- |
| 1 | **DDL 手工纳管**：`01.code/scripts/sql/power_agent_langgraph.sql` | 逐字抄自 `langgraph-checkpoint-sqlite **3.1.2**`（`checkpoints` / `writes` 两张表）；文件头写明**为什么不让框架自己建表**（项目纪律：表结构唯一事实源 = `scripts/sql/`，`db/models/base.py` 禁止 `create_all`）、来源版本、以及"升级依赖时要回来核对" |
| 2 | `app/agent/checkpointer.py` | ① `ensure_schema()` **幂等建表**（既有库无需重建）；② `get_checkpointer()`（`AsyncSqliteSaver` 单例）；③ **两个删除入口**：`delete_threads_in_session()`（在调用方事务内，推荐）与 `delete_threads()`（独立短连接，离线清理）；④ `per_turn_reset()` |
| 3 | `graph.py` 接入 | 编译带检查点的图；`thread_id = conversation_code`；**每轮用 `DEFAULT_STATE` 显式重置过程态** |
| 4 | **`DEFAULT_STATE` 补全** | 从"十几个字段"补成**覆盖全部单轮字段**的完整初始状态——带检查点后 state 跨轮累积，这是防"串轮"的关键 |
| 5 | 删除语义级联 ×2 | `conversation_service.delete_conversation`（删会话）、`auth_service` 的两条路径（清空记录 / 删账号）——都在**同一事务内**清理线程行 |
| 6 | 建库与夹具同步 | `03_init_db.py` 建库时执行新 DDL；`tests/conftest.py` 让测试库与生产库同构（三份 DDL） |

### 为什么"既有库不用重建"要单独处理

`03_init_db.py` 对**已灌数的库会提前返回**（`reports.db` 有数据就 skip）→ 既有安装永远走不到新的 DDL。
因此 `ensure_schema()` 在应用侧补一次幂等执行（`CREATE TABLE IF NOT EXISTS`）。
