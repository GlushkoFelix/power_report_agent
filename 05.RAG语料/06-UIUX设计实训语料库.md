# UIUX设计实训语料库

**主题：** UI/UX 设计文档的结构、交互规范与实训要点
**适用范围：** UI/UX 设计者、前端开发者
**版本：** v1.0

## Q: 对话式数据分析界面的信息架构是怎么定的？

**A:** 采用**三栏布局**，以 1440 宽为设计基准：
- **左栏（240px）**：会话列表（置顶 / 搜索 / 删除）；
- **中栏（自适应）**：消息流与输入区——主战场；
- **右栏（408px）**：结果面板（图表 + 表格 + 解读），可折叠。
全站共 **5 个页面**：登录/注册、对话工作台、报表管理、评测中心、个人中心。
原则是"**先定页面清单与信息架构，再定样式**"——布局定错，后面视觉做多细都要返工。

**标签：** 信息架构, 三栏布局, 页面清单, 设计基准

## Q: 什么是设计令牌（Design Token）？项目怎么落地？

**A:** 设计令牌是把颜色、间距、圆角、字号收敛成一份**命名清单**，
再由它同时生成 CSS 变量与 Ant Design 的主题令牌，避免"每个组件各写一套色值"。
本项目集中在 `src/theme/tokens.ts`：`SEMANTIC_COLORS`（语义色）、`PURPOSE_COLORS`（用途色板）、
`PLOTLY_THEME`（图表主题）、`LEGEND_ITEMS`（图例）与 `themedFigure()`（主题注入函数）。
注意一个技术事实：**Plotly 不认 CSS 变量**，figure 里的颜色必须是字面量，
所以 JS 里还要存一份十六进制色值，与 `index.css` 的 `--c-*` 变量一一对应。

**标签：** 设计令牌, tokens.ts, CSS 变量, Plotly 主题

## Q: 语义色是怎么定义的？为什么峰/平/谷色板与用途色板不能共用？

**A:** 语义色（亮色档实测值）：
**峰 `#E8590C`（橙红）｜平 `#1D4ED8`（蓝）｜谷 `#0CA678`（青绿）｜
未计量 `#7048E8`（紫）｜异常 `#E03131`（红）｜缺采 `#ADB5BD`（灰）**，暗色档各提亮一档。
另有**用途色板**（厨房 / 洗衣房 / 热水器与空调 / 未计量）。
两套色板**互不共用**——这是数据口径红线 **R3（两套拆分不可混加）在视觉层的落地**：
用户一眼就能看出"这几段数据不是同一套口径"，从而减少把两套拆分混着看图造成的误读。

**标签：** 语义色, 色板互斥, 红线 R3, 视觉约束

## Q: 为什么图表颜色不写在后端 figure 里？

**A:** 因为 Plotly 的颜色必须是字面量（不认 CSS 变量），
若后端写死颜色，**暗色主题下就会出现"白底黑字看不清"**；而且导出图片还需要固定亮色底。
因此约定：**后端只写语义色与文案**（`paper_bgcolor` / `font.color` / 网格色一律不写），
主题由前端 `themedFigure(figure, mode)` 在 `Plotly.react` 时注入；
切换主题重新注入即可，不需要后端重发 figure。
唯一例外是导出用的 `EXPORT_LIGHT_LAYOUT`（固定亮色底、2 倍图），那是刻意写死的。

**标签：** 主题注入, 前后端分工, 暗色主题, 导出固定亮色

## Q: 条件芯片（SlotChip）是什么？有哪几种状态？

**A:** 条件芯片是**当前生效查询条件的可视化**，让用户随时看到"系统现在按什么条件在查"，
并能就地修改。四种状态：
① **空**（无该条件时不显示）；② **已选**（显示中文值 + 点 × 清除）；
③ **多值折叠**（超过 3 条时显示 "+N"）；④ **编辑中**（点击弹气泡，确认后自动重算并追加一条消息）。
一条硬要求：**芯片字段域必须与后端 slot 的 8 个字段完全同域**
（`time_range` / `granularity` / `metric` / `dimension` / `filters` / `compare` / `intent` / `chart_hint`），
否则就会出现"编辑芯片 ≠ 改查询"的假交互（`filters` 必须是 `{field, op, value}` 对象数组）。

**标签：** 条件芯片, 四态, slot 同域, 就地编辑

## Q: 图表与表格联动是怎么实现的？

**A:** 点图表数据点 → 表格定位到对应行；点表格行 → 图表高亮对应点。
实现上**不用"猜行序"**，而是让 figure 的 trace 带 `customdata` 携带行号，
点击事件里直接读出行号定位——这样排序、抽稀、TopN 合并之后依然准确。
另外约定：图表类型切换（如折线↔柱状、月粒度↔日粒度）走
`POST /charts/rerender`，**不重新调用模型**，所以是即时的。

**标签：** 图表联动, customdata, 行号定位, rerender

## Q: SSE 事件与界面表现是怎么映射的？

**A:** 每个事件都定义界面反应与目标时延，界面靠"**阶段时间线**"呈现进度：
固定 5 个阶段——**解析问题 → 生成 SQL/代码 → 沙箱执行 → 生成图表 → 生成解读**。
事件映射（10 个）：`status` 推进阶段并显示"正在解析…"；`slot` 更新条件芯片；
`clarify` 插入澄清卡；`code` 展示 SQL/代码块（默认折叠 + "已通过只读校验"标签）；
`table` 渲染结果表；`chart` 渲染图表；`narrative` 打字机式显示解读；
`meta` 填充执行信息面板（耗时 / token / 重试）；`error` 插入错误块；`done` 收尾。
**注意：Schema 注入不单独占一个阶段**——它是会话级前置步骤，单次提问内不重复。

**标签：** SSE 映射, 阶段时间线, 5 阶段, 事件驱动

## Q: 错误与提示分几种呈现层次？

**A:** 五种（UIUX 9.1）：
① **内联校验**——表单/上传字段错误，输入框红描边 + 就地提示；
② **卡片错误块**——分析执行失败（SQL/代码/沙箱超时）：错误码标题 + 原因 +
"已尝试路径" + 明确"本次未生成结果" + 操作按钮（重试/查看代码/字段字典）；
③ **Toast**——鉴权失效、限流、网络异常，右上角 4s 自动消失并带 `request_id`；
④ **拒答卡片**——超出报表范围或预测类问题，**中性灰**（非红色）+ 给出 2 个推荐问法；
⑤ **澄清卡片**——信息不足（时间/指标/报表/粒度未明确），**主色描边** + 可点选选项。
一条关键约定：**红色只留给真正的执行失败与安全拦截**——
澄清用主色、拒答用灰，三者语义必须视觉可分。

**标签：** 错误呈现, 五种层次, 颜色语义, 澄清≠拒答

## Q: 安全拦截在界面上怎么表现？

**A:** 危险请求（`DROP TABLE`、文件访问、提示词注入）必须**显著阻断**：
红描边 2px 卡片 + ⛔ 图标 + 展示被拦截内容摘要（代码形式）+ 命中规则
（如 `sqlglot:non_select`）+ 动作（blocked）+ "已写入安全审计日志"说明；
并且**不提供「重试」按钮**——重试无意义，改为提供「换个问法」引导。
另外规定：命中注入规则时**不展示模型原文与完整 system 提示词**（避免泄露提示词资产）。

**标签：** 安全拦截, 阻断样式, 不提供重试, 提示词保护

## Q: 响应式的四个断点分别怎么处理？

**A:** 以 1440 为基准的四档：
- **≥1440**：三栏全展开；
- **1366–1439**：隐藏副标题、压缩间距；
- **1024–1365**：**右栏收进抽屉**，在输入区上方固定「查看图表与表格」入口；
- **<1024**：单栏 + 会话列表进左侧抽屉。
原则是"**优先保住主链路**"：提问 → 看结论 → 看图表；
不是把三栏等比缩小（那样每栏都不可用）。
注意窄屏最常见的问题就是**用户以为"没出结果"**——所以要保证入口明显、结果生成时给一次高亮。

**标签：** 响应式, 四断点, 右栏抽屉, 主链路优先

## Q: 线框图为什么要先做？与实现不一致怎么办？

**A:** 低保真线框图（本项目 7 张 SVG + PNG）用来**先对齐布局**，避免"边写代码边改布局"。
它与最终实现不一致时，处理方式是：
① 变更后**同步改线框图与文档**；
② 确实无法同步的，在 UIUX 文档的「前端落地记录」章节里**如实记录差异与原因**。
原则是"**不允许文档比实现更漂亮**"——评审对着文档看代码时，差异必须是有据可查的。

**标签：** 线框图, 先线框后视觉, 差异记录, 如实标注
