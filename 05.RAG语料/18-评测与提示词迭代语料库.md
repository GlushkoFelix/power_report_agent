**主题：** 提示词版本演进、评测口径与迭代方法论
**适用范围：** Agent 开发者、评测设计者、答辩准备
**版本：** v1.0

## Q: 项目的提示词都放在哪？有哪些？

**A:** 集中在 `01.code/backend/app/agent/prompts.py`，共三条系统提示词：
- **`SLOT_SYSTEM`**——把自然语言抽成 8 个 slot 字段（增量抽取，只抽本轮变化）；
- **`SQL_SYSTEM`**——生成 SQLite SQL 或 pandas 代码（含"结果形状铁律"等约束）；
- **`PANDAS_SYSTEM`**——生成 pandas 分析代码（输入输出约定、可用库）。
并带一个全局 `PROMPT_VERSION`（当前 **prompt-v3.10**，2026-10-14 起；上一版 v3.9）。v3.10 的两条新规都来自真实错题：**分组维度必须进 SELECT**、**派生列（`*_avg`/`*_ratio`）不可再次聚合**。**v3.10 全量（2026-10-14 晚，四段合并）：108/120 = 90.0%**（首轮 19 题属端点慢时段超时 → 重跑 18/19 通过；与 v3.9 的 116/120 **时段不同、不可直接比较**），写进每条分析记录与每份评测报告——
这样任何数字都能追溯到"哪个提示词版本跑出来的"。

**标签：** 提示词位置, 三条提示词, PROMPT_VERSION, 可追溯

## Q: 提示词从 v3.0 迭代到 v3.9，主要改了哪些？

**A:** 关键节点（每次都有批次证据）：
- **v3.2**：把"结果形状铁律"从用户消息**移到 system 角色**——flash 模型对注入文本的遵从度不足；
- **v3.6**：把 `SQL_SYSTEM` 的"按月份"规则补成两类——**"按 X 汇总"只按该维度分组**（12 行），
  **"看变化/趋势"才保留年份**（48 行），并给判别口诀；
- **v3.7**：把 `SLOT_SYSTEM` 的对比规则写死判别词（比/相比/对比/环比/同比）并给反例，
  修掉"把换主体当对比"（"那 2008 年呢？"）；
- **v3.8**：占比类问题**抽成比率指标** + **换维度的追问要继续继承占比/趋势/排行语义**（修 q115）；
- **v3.9**：`SQL_SYSTEM` 第 14 条补"**先看目标表粒度**"（月表的 `year_month` 一行就是一个月，
  不能照搬日粒度表的写法，修 q111）；
另有一条工程性的：**关闭推理型模型的思考过程**（`LLM_ENABLE_THINKING=false`）。

**标签：** 提示词迭代, v3.2-v3.9, 改动清单, 批次证据

## Q: 提示词迭代中最反复出现的"病"是什么？

**A:** **规则只写了"某一种情形"的写法，没写触发条件与适用范围**，
于是判断标准变成"模型能不能把例子套对场景"——对弱模型不成立。
三次实例：
① 只写"按月看变化用 `substr` 得 48 行"，弱模型套到"按月份汇总"上（应 12 行）；
② 只写"占比抽成比率指标"，没写"换维度的追问继续继承"→ 追问后丢掉比率（q115）；
③ 只写"按 X 分组"，没区分日粒度表与月粒度表 → 月表被降一级（q111）。
**统一修法：每条规则补"触发条件 + 反例 + 判别口诀"**，并加提示词契约测试钉住。

**标签：** 共同病因, 适用范围, 触发条件, 反例与口诀

## Q: 什么时候应该"停止改提示词、改用代码保证"？

**A:** 当出现"**规则早已明文、模型仍不照做**"时。
判断依据是逐题核对生成的 SQL——若错题原因正是提示词里已写明的约束
（如"比率要分子分母重算""求极值要排除 NULL"），继续加文字的边际收益已经很低，
应改成确定性代码：
- 守卫**自动补 `IS NOT NULL`**（求极值，零模型调用）；
- **结果形态自检**（问占比/极值却回明细行、筛选型追问丢分组 → 带原因重写一次）；
- **指标词面兜底**（模型说缺指标但问题里写了 → 驳回并补齐）；
- **规则快通道**（简单问法免一次 LLM 往返）。
这条路线在本项目里被验证为"最可复用"的经验。

**标签：** 何时停改提示词, 代码保证, 四种确定性兜底, 可复用经验

## Q: 评测的"口径"为什么需要专门管理？

**A:** 因为同一个成绩可以有多种口径，混用就会把结论说过头。项目需要同时管四种：
① **单批单配置**（最干净，如 v3.5 × deepseek-v4-flash 的 120 题）；
② **跨批合并**（受额度限制分几批跑，报告头部必须写明"非单批跑出"）；
③ **分层子集**（只跑了部分题，要写明覆盖了哪些题型、哪些没覆盖）；
④ **逐题累计**（把不同时间、不同配置跑出的题拼成 100%，只能说明"题库可解"，不作能力口径）。
另外还要区分**自检（回放 gold）**与**真实模型**——前者不代表模型能力。
报告头部固定写四要素：**模型名 / 提示词版本 / 温度 / 是否合并**。

**标签：** 评测口径, 四种口径, 自检与真实, 报告四要素

## Q: 跑一次全量评测前要做哪些"额度算术"？

**A:** 三步：
① 用小样本测出**单条记录成本**（实测：deepseek-v4-flash 7,144 / kimi-k3 7,374 /
   qwen3.8-max 族 8,342–8,411 tokens）；
② 算记录数：**120 题 = 135 条记录**（15 道多轮题各两轮）；
③ 乘起来与额度比：≈96 万 / ≈100 万 / ≈113 万。
若超额度，可选：**分段跑**（主段用大额度模型跑关键的 100 题，尾段用同族模型剩余额度补完）、
**分层子集**、或换更便宜的同量级模型。反面教材就是"不算就跑"——
跑到一半爆额度会让整批变成"额度错误污染"的脏数据，还浪费了额度。

**标签：** 额度算术, 单条记录成本, 135 条, 分段策略

## Q: "档位取舍"是怎么得出来的？

**A:** 用同一提示词（v3.9）跑两个档位对照：
- **质量档** `qwen3.8-max`：主段 100 题 **100.0%**，但平均 11.0s / P95 20.5s（延迟未达标）；
- **速度档** `qwen3.7-flash`：97 题 **93.8%**，单轮批 8.1s / P95 10.3s（**延迟达标**）。
结论：**准确率与延迟在现有档位上不可兼得**；由于 N2/N3 是硬指标，
默认应选速度档，把质量档留给"要准确率、不要延迟"的场景或做成用户可切换档位。
此外还有**第三条线——额度成本**（qwen-max 族单份 1M 装不下完整 120 题），
选型时要三条线一起看。

**标签：** 档位取舍, 质量档, 速度档, 三条取舍线

## Q: 评测报告应该包含哪些内容？

**A:** 六块：
① **头部**：批次号、执行模式（真实/自检）、模型、提示词版本、温度、是否合并；
② **总体指标**：题量、执行正确率、结论命中率、平均与 P95 耗时、首字延迟、重试次数；
③ **分类正确率**：按题型、按难度、按陷阱题（含覆盖的红线）；
④ **差异与失败分布**：diff_type 分布、错误码分布、判分档命中分布、重试分布、五类归因；
⑤ **逐题明细**：题号 / 题型 / 难度 / 是否陷阱 / 结果 / 判分档 / 差异类型 / 耗时 / 重试 / 错误码；
⑥ **错题复盘**：生成 SQL vs 标准 SQL、结果差异、根因分析。
报告是 Markdown（可下载、可转 PDF），且数字与结构化明细**同源**。

**标签：** 评测报告, 六块内容, 逐题明细, 错题复盘

## Q: 评测暴露过哪些真实产品缺陷？

**A:** 有代表性的几条：
① **评测工具自身"串味"**——整批共用一个会话，前一轮的过滤条件（如 `is_weekend=1`）
   串进了后面的题，导致误判为模型答错 → 修法是首轮显式 `slot_base={}` 不继承；
② **slot 超时阈值与兜底规则按快档定的**——换慢档模型后频繁触发超时，
   加上兜底"多指标一律拒绝"，把 5 道可答对的题判成失败 → 修为超时 12s + 兜底允许多指标；
③ **q096 跨模型复现"拿不到结果"**——真因是**澄清轮**（问"表里有多少行"没有用电指标，
   被判缺指标 → 返回澄清卡、不落记录），修法是补"元数据类指标"词面兜底；
   顺带把评测里"澄清轮被记成结果为空"的描述改为 `clarify_no_result`（此前会把排查带偏）；
④ **审计白名单漏改导致告警静默失败**——约束是 CHECK 白名单，新增事件类型没同步改，
   插入被拒且被 `try/except` 掩盖 → 补齐白名单 + 幂等迁移脚本 + 回归用例。
共同教训：**缺陷要读到"生成的 SQL / 落库的数据"才能定位**，只看"对错"会归因错方向。

**标签：** 真实缺陷, 评测工具缺陷, slot 超时, q096, 审计白名单

## Q: 迭代的"验收纪律"是什么？

**A:** 四条：
① **每次改动都要有验证**——小样本批次或单题复跑，用数字说话（不接受"应该修好了"）；
② **新用例钉住规则**——凡是被修掉的缺陷/口径，都补一条测试防复发；
③ **如实登记未达标**——不能因为"改了"就默认"达标了"；
④ **版本与证据链完整**——提示词版本号、批次号、报告文件三者能对上，
   任何结论都能回溯到"哪一批、什么配置、什么原始数据"。

**标签：** 验收纪律, 小样本验证, 用例防复发, 证据链
